Guía de Integraciones

Cómo consultar la API propia y revisar los webhooks recibidos y enviados, organizados por empresa.

Acceso exclusivo de Administrador

La pestaña reúne la consola API y dos historiales de webhooks independientes. La autorización se comprueba en el servidor.

1. Acceso a Integraciones

Inicia sesión con una cuenta de Administrador y selecciona Integraciones en el menú principal. También puedes abrirla directamente:

  • XAMPP local: http://127.0.0.1:8002/index.php?action=integraciones
  • Docker: http://localhost:8080/index.php?action=integraciones

La página sólo está autorizada para Administrador. Conocer la dirección no concede acceso a otros roles.

3. Usar la API propia

Los recursos disponibles son alumnos, empresas, ofertas, convenios y asignaciones. La consola permite elegir método, recurso, ID opcional y paginación.

  1. Abre Tokens API desde la consola y crea un token para una cuenta activa.
  2. Copia el valor completo cuando se muestre y guárdalo de forma segura: sólo se muestra una vez.
  3. Introduce el token en la consola, selecciona los parámetros y envía la solicitud.
  4. Revoca el token cuando ya no lo necesites.
Precaución con las escrituras. GET consulta. POST y PATCH pueden guardar cambios permanentes en la base compartida. Revisa el JSON antes de confirmar. No uses datos personales.

El token se borra del campo tras cada solicitud. El servidor aplica los permisos del rol y conserva sólo el hash del token.

4. Webhooks recibidos

El historial muestra eventos enviados a la aplicación: tipo, fecha, identificador, JSON recibido y, cuando está disponible, código y cuerpo de respuesta HTTP.

El evento se agrupa con la empresa indicada por data.empresa_id, siempre que sea un identificador válido de una empresa existente en la base actual. Si falta o no se puede asociar, aparece en Sin empresa identificada. El sistema no deduce la empresa usando nombres o correos.

Recibir un webhook lo archiva; no crea ni modifica datos académicos. El historial es de consulta.

5. Webhooks enviados

El historial muestra eventos encolados por Sistema FCT. Dentro de cada grupo de empresa, aparecen primero los más recientes. Se puede revisar estado, intentos, HTTP, JSON enviado, respuesta del receptor y último error.

  • Se usa data.empresa_id cuando es válido.
  • En eventos de convenios y ofertas se identifica la empresa desde el registro relacionado.
  • En eventos de prácticas se sigue la relación de la asignación a su oferta.
  • Si no se identifica una empresa existente, el evento queda bajo Sin empresa identificada.

Se muestran hasta 500 eventos por historial. La página permite inspeccionarlos, pero no reintenta ni reenvía eventos.

6. Pruebas locales

La herramienta administrativa separada Pruebas API y webhooks permite probar solicitudes de API y eventos webhook sintéticos. En XAMPP:

http://127.0.0.1:8002/index.php?action=pruebas-integracion

El recorrido de webhook utiliza el receptor local y no configura un servicio externo. Los eventos sintéticos pueden quedar archivados; usa datos ficticios. La configuración completa está en docs\webhooks.md.

7. Seguridad y ayuda

  • No publiques tokens, secretos, capturas con credenciales ni datos personales.
  • Revoca tokens temporales al terminar.
  • Los eventos sin empresa identificable no se reasignan automáticamente.
  • Si los listados fallan, comprueba MariaDB y que las migraciones webhook estén aplicadas.
  • Un GET directo al receptor puede responder 405 Método no permitido; es normal porque espera POST.

Consulta docs\api-rest.md para los recursos de la API y docs\webhooks.md para firmas, configuración y worker.
